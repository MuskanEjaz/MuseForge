# Persistent Shareable Portfolio Links Setup

MuseForge can run in two modes:

1. **Local mode** — public portfolio links are saved in a local JSON file at your computer's `.museforge` folder.
2. **Production mode** — public portfolio links are saved in Supabase so they survive backend restarts, redeployments, and server moves.

For competition submission and deployment, use **Production mode**.

---

## Why this matters

A local JSON file is fine for testing, but it can disappear when a cloud server redeploys. Judges need portfolio links that remain available after deployment. Supabase gives MuseForge a persistent database-backed link store.

---

## Step 1 — Create a Supabase project

1. Open Supabase.
2. Create a new project.
3. Choose a project name such as `MuseForge`.
4. Save the database password somewhere safe.
5. Wait until the project finishes creating.

---

## Step 2 — Create the portfolio table

Open **SQL Editor** in Supabase and run this SQL:

```sql
create table if not exists public_portfolios (
  id text primary key,
  portfolio_data jsonb not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index if not exists public_portfolios_created_at_idx
on public_portfolios (created_at desc);
```

This table stores each public portfolio as JSON using the same data structure generated by MuseForge.

---

## Step 3 — Copy your Supabase API values

Go to:

```text
Project Settings → API
```

Copy these values:

```text
Project URL
service_role key
```

Important: The `service_role` key is private. Keep it only in `backend/.env` or your deployment provider's backend environment variables. Never put it in frontend `.env`, GitHub, screenshots, or README.

---

## Step 4 — Add values to `backend/.env`

```env
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your_service_role_key_here
SUPABASE_PORTFOLIOS_TABLE=public_portfolios
```

Restart the backend after changing `.env`:

```powershell
cd backend
node server.js
```

---

## Step 5 — Check backend health

Open:

```text
http://localhost:5000/health
```

If Supabase is configured correctly, the JSON response should include:

```json
"publicPortfolioStorage": "supabase"
```

If it says:

```json
"publicPortfolioStorage": "local-json"
```

then Supabase is not configured and MuseForge is using local testing storage.

---

## Step 6 — Test the share link

1. Generate a portfolio.
2. Click **Create Share Link**.
3. Open the generated `/portfolio/...` link.
4. Restart the backend.
5. Open the same link again.

If the link still opens, persistent storage is working.
